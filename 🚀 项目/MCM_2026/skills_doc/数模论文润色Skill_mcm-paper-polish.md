# 数模竞赛论文润色（MCM/研赛版）

## 定位

把**已经写好的**数模竞赛论文稿，改得更清楚、更地道、更像人写的、更对评委胃口。

这是 `paper-polish` 的竞赛改造版。投稿论文的那套规范（Introduction 定位、prior work 公平、期刊语气）在这里不适用；取而代之的是**数模竞赛论文的标准结构与评委视角**。

## 何时使用

- 用户写好了一段/整篇数模论文，想改进表达。
- 用户说「润色一下」「改改措辞」「别这么像 AI 写的」「摘要帮我压一压」「这段读着别扭」。
- 用户要做**摘要定稿**（数模第一评分点）。

## 何时不用

- 还没有稿子，要从头写 → 用 `paper-writer`（若是期刊投稿论文）。
- 要规划论文逻辑骨架 → 用 `tech-paper-template`。
- 要审稿人式批判审查 → 用 `pre-submission-reviewer`。

## 🔴 最高铁律：忠实于团队原意

润色的第一原则，也是参赛队最怕的事：**编辑者偷偷改掉了论文想说的话。**

- 不悄悄把结论说强或说弱（「可以认为」→「证明了」）——除非明确告知并等确认。
- 不把相关性说成因果。数模里「降雨导致成灾」这类极易被写歪：数据支持的是**关联/临界条件**，不是物理因果，除非我们建立了因果机理模型。
- 不删限定条件（「在 1990–2020 年数据范围内」）让它看起来是普适结论。
- 不因为觉得啰嗦就砍掉某个论证。**建议删，不要自己删了还叫润色。**

判定标准：
> **纯语言改动**（语法、语序、等义换说法）→ 随便改。
> **可能碰含义的改动** → 要么不做，要么做了**明确标注等确认**。
> 拿不准 → 一律当第二类。

自查：润色稿与原稿并排，逐句问「这句的科学含义还是原来那句吗？」每个「不太是」都是必须标注的地方。

## 🚫 绝不编造

润色 = 把已写的说得更好，**不是补内容**。禁止添加：
- 数据、数字、阈值、参数、实验结果；
- 方程（原文没有就不许「顺手补一个」）；
- 引用、文献；
- 方法名、模型名、机理解释。

某段缺证据 → **留括号提示给团队**：
> `（此处建议补上该项的原始数据支撑）`
> `（这一步是我的推断，原文未写，请确认）`

## 保守优先

默认**轻改动**：宁小改不大改，宁不改不小改。
作者已经写谨慎了（「可能」「在一定程度上」）→ **不许「帮」他改强**。
要动结构 → **停下来问**，让团队选「轻润色」还是「深度重写」。

## 一轮润色流程

```
1. 先读懂 → 这段在说什么？在论文哪个位置（摘要？模型建立？灵敏度分析？）
2. 找真问题 → 表面语法，还是逻辑本身坏了（几件事挤一段、有结论没支撑、
              相关性写成因果）？逻辑坏了 → 句子润色救不了，建议重写该节。
3. 改 → 在忠实原则内让它更清楚、更地道、更像人写的。
4. 交代改动 → 给干净成品 + 简要说明（尤其碰含义的）。
```

# 数模竞赛论文标准结构

润色前先确认这段属于哪一节，**不同节语气不同，不要一个调子到底**。

| 章节 | 任务 | 常见毛病 |
|---|---|---|
| **摘要** | 全篇缩影，第一评分点 | 没结论、没量化结果、写成目录式罗列 |
| **问题重述** | 用自己话重述 + 分析 | 直接抄题目原文（评委反感） |
| **模型假设** | 列出简化假设并说明依据 | 假设与后面模型脱节，或假设过强不说明理由 |
| **符号说明** | 符号表，全文统一 | 符号定义与正文不一致，同一个量两个符号 |
| **模型建立** | 从问题到数学形式 | 只有结论没有推导；变量/目标/约束没写全 |
| **模型求解** | 算法 + 结果 | 只说「用 XX 算法求解」，不讲为什么、不给伪代码/流程 |
| **灵敏度分析** | 改参数看结果稳定性 | 只给图不解释；没有临界值/稳定区间结论 |
| **模型评价** | 优缺点 + 改进方向 | 只说优点；缺点写成「时间不足」这种敷衍话 |

## 摘要专章（最重要）

数模摘要不是「目录」，是「**微型论文**」。评委常先只读摘要。

**推荐四段式**：
```
① 问题背景与方法总述（1–2 句，点到具体方法名）
② 针对问题一/二/三：做了什么 + 得到什么「量化结果」
③ 亮点/创新（1 句，克制，不吹）
④ 关键词（3–5 个）
```

**摘要必须出现的东西**：
- 具体方法名（不能只写「建立了数学模型」）
- 关键数字结果（如「脆弱区面积约 X 万 km²」「误差降至 Y%」）
- 分问题对应（问题一…问题二…问题三…）

**摘要禁止**：
- 「本文…本文…本文…」句式堆叠
- 无数字的定性描述
- 图表引用（摘要里一般不放图）
- 过度自夸（「完美解决」「国际领先」）

## 中文优先

数模竞赛默认**中文写作**。除团队明确说要英文稿，一律输出中文。
不要因为用户用中文打字就猜输出语言——这里中文就是默认。
（若确需英文稿，按 `paper-polish` 的「中译英」流程：先抽意思再写句子，补省略逻辑，术语一致，不加码。）

# 术语与公式一致性（数模特有硬伤）

这是数模论文最容易被评委抓的问题，专门查：

- **符号统一**：同一个量全文一个符号；不同量不用同一个符号。第一处定义，后文沿用。
- **符号与文字对应**：正文说「坡度 S」符号表里就得有 S。
- **公式引用**：正文提到「式(3)」必须确实存在且内容对得上。
- **模型名统一**：同一个模型不换名字（别一会儿「评价模型」一会儿「评估体系」）。
- **单位统一**：全文单位一致，图表轴标单位。
- **图表编号与引用**：说「如图 5 所示」图 5 就得是那张；图必须有编号、标题、可读坐标轴。

查完给团队一份**问题清单**（不要自己猜着改符号，符号改动牵一发动全身，必须团队确认）。

# 去 AI 味（数模尤其关键）

**赛题明文警告**：查重发现 AI 生成内容与其他队雷同 → 判违规受罚。

所以这一节对数模比投稿论文更重要。扫查典型信号并改写：

- **宏大框架**：堪称典范、具有里程碑意义、开启了新篇章 → 删，换成具体事实。
- **空洞 -ing 尾巴**：体现了…、彰显了…、凸显了…、为…保驾护航（句尾装饰）→ 展开成真分句或删。
- **营销形容词**：强大、卓越、丰富（比喻义）、深刻、令人惊叹 → 删。
- **模糊归因**：研究表明（无出处）、业内人士指出 → 给真实出处或删。
- **高频 AI 词**：深入探讨、层层递进、赋能、助力、深度融合、有机结合、至关重要、值得注意的是、不难发现 → 换朴素说法。
- **不必要系词堆砌**：起到了…的作用、扮演着…的角色 → 用「是」「有」。
- **强行三段式/负向排比**：不仅…而且…、既…又…（为对称而对称）→ 直说。
- **同义反复**：一个东西一段里换三个名字 → 定一个名字。
- **连字符堆叠**：数据驱动型、端到端、实时化 当装饰堆 → 留必要术语，砍装饰。
- **断头标题**：标题下一句话又把标题说一遍 → 删或并入正文。
- **格式噪声**：过多破折号、机械加粗、emoji、中文弯引号滥用。
- **聊天口吻**：好问题、希望有帮助、你说得对 → 删。
- **冗赘与过度对冲**：为了（用「为」）、由于…的原因（用「因为」）、可能或许大概 → 用「可能」。

收尾自查：问「这段还有哪里读着像机器写的？」列出残留信号，再改到不像。

**⚠️ 剥干净后可能变得干净但没气**。补救（仍不编事实、不加码）：句长有变化、用精确数字压重量而非堆形容词、直白说清取舍与局限。**生命力来自精确和诚实。**

## 夸张词黑名单（软化或标注，除非数据真撑得住）

**中文**：卓越、首次、唯一、最高、完美、碾压、遥遥领先、颠覆性、最优、极大提升、显著优于（无统计检验时）。
**英文**：extraordinary, unprecedented, revolutionary, groundbreaking, best, superior, state-of-the-art, proves, conclusively, first (without evidence).

安全替代方向：
- 首次 → 「据我们所知，首次」或限定范围（「在本文数据集上」）
- 最优/最佳 → 「在测试条件下表现最好」/「优于对照组」
- 证明 → 依证据用「表明」/「说明」/「支持」
- 极大提升 → 给具体百分比

要点不是弱化每个强词，而是**让宣称强度匹配证据强度**。证据强且范围写清时，强动词是对的。

# 评委视角自查（不是审稿人视角）

投稿审稿人关心新颖性和严谨性；**数模评委关心三件事**：

1. **模型是否解决了他问的那几个问题**（答非所问最致命）
2. **结果是否有量化支撑**（有没有数字、图、表）
3. **是否看得懂、写得清**（摘要 + 结构 + 图表）

润色完通读一遍，逐一问：
- [ ] 每一问（问题一/二/三/四）是否都有明确对应的章节和结果？
- [ ] 摘要里有没有具体方法名 + 关键数字结果？
- [ ] 结论是「模型算出来的」还是「编的」？（必须是前者）
- [ ] 灵敏度分析有没有、结论有没有说清？
- [ ] 符号、公式、图表编号是否全文自洽？
- [ ] 有没有 AI 味残留（对照上一节清单）？

# 交付方式

核心永远是**干净成品**（团队能直接用）。

1. 先给**润色后文本**（连贯成文，不逐行标注）。
2. 再简要说明主要改动（**3–5 条够了**）。
3. 明确说：哪些改动**可能碰了科学含义需确认**；哪里**建议补数据但没编**。
4. 碰含义的改动 → **原句 | 改后 | 为什么 | 风险** 对照列，让团队一眼能定。
5. 若某段不补内容就没法修 → **坦白说**，别用好听话糊过去。

## 文件 vs 粘贴文本

- 稿子在 workspace 文件里（Word/Markdown/LaTeX）→ **直接改文件**，用 diff 当改动记录，然后只列「碰含义需确认」的几项。
- 用户粘贴在对话里 → 回复里给**完整润色后文本** + 改动说明。

## 长文分块

数模论文长，**不要前几页精雕后几页糊弄**。要分块就标「第 i 块 / 共 N 块」，每块都是完整可用的。**跳过部分不许说全润过了。**

## 读不了的内容

公式是图、表格窜行、图看不清 → **不许猜着写**。明确告诉团队在哪、需要人工核对。

# 什么时候「润色救不了」

两种情况，处理方式不同：

1. **文字已超出句子级修复**：逻辑链断、模型与问题对不上、一节写了两件不相干的事 → 这是内容问题。说出来，建议重写该节。
2. **核心结论本身站不住**：比如结果被简单基线打平 → **不替它辩护、不编乐观解读**。直说，建议先自查模型与数据。

> 诚实指出问题，比润色掉它更有帮助。

# 附录 A：数模竞赛论文分章节写法规范

> 本文件是 mcm-paper-polish 的细版参考。每节列出：必须回答什么、推荐顺序、常见毛病。

## 目录

5. 模型建立

---

## 摘要

**必须回答**：这是什么问题？用了什么方法？得到什么量化结果？亮点在哪？

**推荐顺序（四段式）**：
1. 背景 + 方法总述（1–2 句，点到具体方法名）
2. 逐问交代：问题一 → 方法 + 结果数字；问题二 → …；问题三 → …
3. 亮点/创新（1 句，克制）
4. 关键词 3–5 个

**常见毛病**：
- 写成目录（「本文首先…然后…最后…」），没有结论
- 只有方法名没有结果数字
- 不分问题，一段糊到底
- 「完美」「高效地解决了」这类空话

**禁止**：图表引用、过度自夸、「本文」句式堆叠。

---

## 问题重述

**必须回答**：题目要我们做什么？我们把它理解成了什么？

**推荐顺序**：用自己的话概述背景 → 提炼每一问的求解目标 → 点出本题的关键难点。

**常见毛病**：
- 直接复制粘贴题目原文（评委一眼看穿，扣印象分）
- 只抄题目不做分析，看不出队伍理解了什么
- 漏掉某一问

---

## 模型假设

**必须回答**：我们做了哪些简化？理由是什么？

**推荐顺序**：逐条列假设 → 每条后附一句依据（物理常识 / 数据说明 / 文献）。

**常见毛病**：
- 假设与后面模型脱节（假设说各向同性，模型里却用了方向性参数）
- 假设过强却不说明理由
- 假设太多太碎，把不重要的一堆凑数

---

## 符号说明

**必须回答**：全文用了哪些符号，各代表什么、什么单位？

**推荐顺序**：表格列出「符号 | 含义 | 单位」；按出现顺序或按类别分组。

**常见毛病**：
- 符号表与正文不一致（正文用了未列入的符号）
- 同一个量两个符号
- 不写单位

---

## 模型建立

**必须回答**：从实际问题到数学形式，每一步怎么来的？

**推荐顺序**：
1. 明确决策变量（我们能定什么）
2. 明确目标函数（要最优什么）
3. 明确约束条件（什么不能越）
4. 写出形式化模型 `min f(x) s.t. g(x)≤0, h(x)=0`
5. 解释每个式子的物理/现实含义

**常见毛病**：
- 直接甩出公式，没有推导过程
- 变量/目标/约束没写全（三零件缺一）
- 公式与文字对不上号
- 没有解释式子的现实含义

---

## 模型求解

**必须回答**：用什么算法、为什么、怎么实现、结果如何？

**推荐顺序**：算法选择理由 → 算法流程（伪代码或步骤）→ 实现环境与参数 → 求解结果（表/图）→ 结果解读。

**常见毛病**：
- 只说「用遗传算法求解」，不讲为什么选它、不和其他方法比较
- 没有伪代码/流程图，评委无法复现
- 只给结果图不解读
- 不写求解环境（软件、版本、耗时）

**可复现性必写**：编程语言、求解器名称与版本、关键参数、随机种子、运行耗时。

---

## 灵敏度分析

**必须回答**：参数变了结果怎么变？结果稳不稳？临界值在哪？

**推荐顺序**：选关键参数 → 设定变动范围 → 给出结果变化图/表 → 结论（稳定区间、临界点、影响排序）。

**常见毛病**：
- 只给图不给结论
- 参数选得随意，不选真正关键的
- 没有临界值/稳定区间的定量结论
- 视为可选项（**这是数模拉分点，必做**）

---

## 模型评价与推广

**必须回答**：模型好在哪、差在哪、还能怎么用？

**推荐顺序**：优点（3 条以内，具体）→ 缺点（诚实，具体）→ 改进方向 → 推广场景。

**常见毛病**：
- 只说优点
- 缺点写成「时间不足」「数据有限」这种敷衍话
- 改进方向空洞（「未来可以进一步完善」）

**写法提示**：缺点要写成**可操作的改进点**，如「未考虑 X 因素，可通过引入 Y 数据加以改进」。

---

## 参考文献与附录

- 参考文献格式统一（GB/T 7714 或题目要求），正文引用与文末条目一一对应。
- 附录放代码、数据表、补充推导；**代码要能跑**，别贴伪代码。
- **AI 使用披露**：若题目要求披露 AI 使用情况，按题目格式在附录写清楚「用了什么工具、输入什么、如何后续处理」。

# 附录 B：AI 味检查清单与夸张词表

> 本文件是 mcm-paper-polish 的细版参考。
> 数模赛题明文警告：查重发现 AI 生成雷同 → 判违规。故本清单对数模尤其关键。

## 一、AI 味典型信号（逐条扫，命中就改）

- **宏大框架**：堪称典范、具有里程碑意义、开启了新篇章、标志着一个新阶段 → 删，换具体事实。
- **浅层 -ing 尾巴**：体现了…、彰显了…、凸显了…、为…保驾护航、奠定了坚实基础（句尾装饰）→ 展开成真分句或删。
- **营销形容词**：强大的、卓越的、丰富的（比喻义）、深刻的、令人惊叹的、in the heart of 式修辞 → 删。
- **模糊归因**：研究表明（无出处）、业内人士指出、有观点认为 → 给真实出处或删。
- **高频 AI 词**：深入探讨、层层递进、多维度、全方位、赋能、助力、深度融合、有机结合、至关重要、值得注意的是、不难发现、一言以蔽之、在…的背景下 → 换朴素说法。
- **系词堆砌**：起到了…的作用、扮演着…的角色、作为…的存在 → 用「是」「有」。
- **强行三段式 / 负向排比**：不仅…而且…、既…又…（为对称而对称）、从 X 到 Y（两端不同量级）→ 直说。
- **同义反复**：一个对象一段里换三个名字 → 定一个名字，全文沿用。
- **连字符堆叠**：数据驱动型、端到端、实时化、智能化（当装饰堆）→ 留必要术语，砍装饰。
- **断头标题**：标题下一句话又把标题说一遍 → 删或并入正文。
- **格式噪声**：过多破折号、机械加粗、emoji、中文弯引号滥用、全角半角混用。
- **聊天口吻**：好问题、希望有帮助、你说得对、让我来为你解答 → 删。
- **冗赘与过度对冲**：为了（用「为」）、由于…的原因（用「因为」）、可能或许大概、在一定程度上可能 → 用「可能」。

**收尾自查**：问「这段还有哪里读着像机器写的？」列出残留信号，再改到不像。

**⚠️ 剥干净后可能变得干净但没气**。补救（仍不编事实、不加码）：
- 句长有变化（长短交替）；
- 用精确数字压重量，而不是堆形容词；
- 直白说清取舍与局限。

**生命力来自精确和诚实。**

## 二、夸张词黑名单（软化或标注，除非数据真撑得住）

**中文**：卓越、首次、唯一、最高、完美、碾压、遥遥领先、颠覆性、最优、极大提升、显著优于（无统计检验）、革命性、开创性。

**英文**：extraordinary, exceptional, remarkable, unprecedented, revolutionary, groundbreaking, best, superior, state-of-the-art, proves, conclusively, perfectly, first (without evidence), innovative, pioneering, transformative。

**安全替代方向**：

| 原文 | 替代 |
|---|---|
| 首次 | 「据我们所知，首次」或限定范围「在本文数据集上」 |
| 最优/最佳 | 「在测试条件下表现最好」/「优于对照组」 |
| 证明 | 依证据用「表明」/「说明」/「支持」 |
| 极大提升 | 给具体百分比 |
| 完美解决 | 「较好地解决了」/「在该假设下解决了」 |
| 显著优于 | 「优于」（若无检验则不能加「显著」） |
| conclusively | 删，或「to our knowledge」 |
| best / superior | among the strongest / performs competitively |

要点不是弱化每个强词，而是**让宣称强度匹配证据强度**。证据强且范围写清时，强动词是对的。

---

## 三、动词强度阶梯（按证据选词）

| 强度 | 中文 | 英文 | 适用 |
|---|---|---|---|
| 强 | 表明、证明、确立 | show, demonstrate, establish | 证据扎实、可复现 |
| 中 | 说明、指示、与…一致 | suggest, indicate, be consistent with | 合理但开放 |
| 弱 | 可能反映、似乎、提示 | may reflect, appears to | 推测 |

---

## 四、一句话总结

去 AI 味和去夸张是同一件事的两面：**让文字诚实**。
没有携带零信息的语气；没有证据撑不住的宣称。
**只改表达，绝不改事实**——不许编数据、编实验、编引用来撑强结论。
