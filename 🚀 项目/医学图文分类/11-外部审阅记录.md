## 三、创新点逐条裁决（I1~I5）

### I1 · CP-CLIP 的 p 动态化 → **保留，但不能单独立项（降为"组件"）**

**裁决：保留，优先级从"P0 主业"降为"P0 组件"**

**理由（尖锐版）**
1. **新意强度不够**。p 从标量超参变成样本级预测，本质是 **hyperparameter → conditional computation** 的标准套路。在 CV 里这类工作（dynamic network / sample-adaptive gating）已经非常成熟，评委不会认为这本身构成创新。
2. **你自己的卡片里就写着撞车证据**：CP-CLIP 卡的"后续工作"节记了 **Med-Align（IEEE BigData 2025）"还加了自适应节点比例（按 loss 动态调核心节点比例）"**。**这已经就是 I1 了。** 你在 `06-创新点池` 里把 I1 定 P0 时，**没有把这个已知撞车写进风险栏**——这是流程失误。
3. **退化成 p≈1 的风险被低估**。CP-CLIP 作者自己说 p=1 退化为普通全连接（可接受极端）。那么一个被训练的 router 会**最快地收敛到"全连接最省事"**——你需要一个**反向约束**（比如对 p 的熵正则、或对稀疏度的显式预算），这部分才是真工作量，而库里完全没提。
4. **验证成本被低估**。`09` 层三里写"先在 CP-CLIP 复现基线上加 2 层 MLP router"——**但你的 07 明确写了本机无 GPU**。这意味着 I1 的前置条件是"复现 CP-CLIP"，而复现本身需要原文全部超参（你卡片里没有数字）。

**建议改法（如果要做，这么做才有戏）**
> 不要把 I1 写成"动态 p"。写成：**"核心—外围划分的样本自适应与可解释性归因：一个 p 由什么决定？"**
> - 先做**诊断实验**（不需要新方法就能发 workshop）：固定最优 p 在不同样本上的表现差异有多大？差异是否与病灶面积/对比度/文本长度相关？**如果差异不显著，I1 直接死掉，省你三个月。**
> - 只有诊断显示"最优 p 样本间方差显著"，才值得做 router。
> - 卖点不要放在"我加了 router 涨了 0.8 点"，放在"**我证明了核心比例应该由 X 决定，并给出可控机制**"。

**裁决：保留方向，但**必须换靶子****

**理由**
1. **"加可学习边权"= 退化风险极高**。把二值 A 改成可学习 A，最优点很可能就是"全 1"（回到普通 MLP），因为**没有任何监督信号告诉模型"外围之间不该通信"**。你库里风险栏自己写了这一点，但没给解法。
2. **⭐ 关键未知（这是你目前最该去查的一件事）**：**CP-CLIP 的核心/外围是怎么切出来的？** 如果是**按神经元索引硬切**（前 n 个是核心），那"核心/外围"就是一个**任意的排列假设**——网络里神经元本来是可交换的，这个划分在数学上没有语义。这个"神经元分配"问题作者自己在 Discussion 承认了（你卡片记了"所有神经元同等对待"）。→ 那么 **I2 真正的空白不是"关系没建"，而是"核心/外围的划分本身没有语义依据"**。这比"加边权"有价值得多。
3. **撞车风险**：CP-CLIP 的第二条任务线（critical region detection）说明"改结构 → 提可解释性"这条路他们自己在走；Med-Align 也在走。

**建议改法**
> 把 I2 重写为两条候选，二选一：
> - **I2-a（推荐，更硬）**：**"核心—外围划分的语义化"** —— 不再按神经元索引硬切，而是让划分由**解剖/病灶先验**或**梯度归因**决定，并与"关键区域检测"指标挂钩。这条要和 CP-CLIP 的可解释性任务正面对比。
> - **I2-b（保守，更好发）**：**"外围到底该不该丢"** —— CP-CLIP 说"外围不是丢掉是隔离"。那就做一个**受控实验**：外围→核心单向 vs 双向 vs 外围互连 vs 完全图，在**零样本**指标上排个序，用**理论分析**（信息瓶颈 / 有效秩）解释。这是"诊断型论文"，工作量对研一友好。
> - ❌ 不要做"加可学习边权然后报告涨点"——那是典型的三无增量工作。

## 六、结构建议

### 6.1 这套结构对这个目标够用吗？——**方向对，但有一个致命的结构缺陷**

**致命缺陷：你的库是"以方法为中心"的，而你要做的是"以缺口为中心"的。**

现在的链路是 `方法卡 → 痛点 → 想法`。**方向的起点错了**：你是先读了 5 篇，再从 5 篇里反向推痛点。这就是为什么 21 条痛点里有一半是"某方法的实现细节"，也解释了 4.3 那个方法论错误（用 5 篇样本判领域空白）。

**正确的做法**：加一层 **"领域级扫描"** 在方法卡之前。

```
现在：  01背景 → 02脉络 → 03任务 → 04痛点 → 05方法卡 → 06想法
                             ↑
                       痛点的来源是 05，循环依赖

应该：  01背景 → 02脉络 → [NEW 02.5 领域扫描] → 04痛点 → 05方法卡 → 06想法
                              ↑ 用检索量/命中数定痛点，而不是用读过的卡定痛点
```

**02.5 领域扫描该放什么**（一页就够，但必须做）：
- 对每条痛点，在 OpenAlex / Google Scholar 搜该痛点的关键词组合
- 记录：**命中数、最近 2 年的相关工作 3 篇、是否已有专门基准**
- 判定：`真空白（0 相关）` / `有人做但未解决（有相关）` / `已解决（有基准）`

> **没有这一页，"整行空白 = 机会"永远是拍脑袋。**
