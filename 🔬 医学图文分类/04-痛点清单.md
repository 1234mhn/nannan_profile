# 04 · 痛点清单【核心】

> 组织方式：按**「质疑对象」**分类。同一个对象的痛点放一起，方便看出「这块被质疑过几次、还剩什么」。
> 每条写五件事：痛点描述 / 谁提出的 / 证据 / 是否已被解决 / 剩余空间。
> 状态分为：✅已解决 ｜ 🟡部分解决 ｜ ❌未解决 ｜ ❓待确认

---

## A. 质疑架构（「模型结构本身该不该长这样」）

### A1. 双塔没有交互，图文只是"站好位置量距离"
- **描述**：CLIP 式对比学习把图文映射到同一空间算相似度，两个编码器之间没有交互，无法在编码阶段利用对方信息。
- **谁提出的**：融合派（ViLBERT/BLIP）；医学侧 [[MedViLL]]、CheXmix。
- **证据**：`📚 理论知识/多模态/图像文本分类理解.md` 两大流派对照表；MedViLL 精读笔记"图像和文本从一开始就一起学"。
- **是否解决**：🟡 部分。融合派解决了交互，但代价是训练成本与数据量。
- **剩余空间**：**融合派在数据稀缺的医学场景是否总是更优？** 尚未见到系统对照（我的推导，❓待确认）。
→ 联动见 [[09-联动与索引]]

### A2. 投影层会扭曲视觉特征
- **描述**：LLaVA 式「CLIP 编码器 + 投影层 + LLM」中，投影层把视觉细节压掉，而医学的细微征象恰恰在细节里。
- **谁提出的**：CheXmix（Stanford AIMI，arXiv 2604.22989）。
- **证据**：memory/2026-10-26「反对 LLaVA 式两段拼装：投影层会扭曲视觉细节」。
- **是否解决**：🟡 部分。CheXmix 用 VQ-GAN 图 token 化 + 早期同序列融合消除投影层；
  但**检索任务没赢**，**低掩码率 0-20% 打不过 SigLIP**（作者如实写了）。
- **剩余空间**：token 化本身是有损压缩（1024 个 token 表示一张胸片），**压缩率与保留细节之间的权衡未被系统研究**（我的推导）。
→ 联动见 [[09-联动与索引]]

### A3. MedViLL 的早期融合需要复杂掩码设计
- **描述**：MedViLL 用多模态注意力掩码控制信息流，一套模型兼顾理解与生成，但掩码规则复杂。
- **谁提出的**：CheXmix（"掩码从核心创新退成不需要"）。
- **证据**：memory/2026-10-26 的 MedViLL vs CheXmix 对比。
- **是否解决**：🟡 部分。CheXmix 用统一因果 + 不同生成目标替代掩码。
- **剩余空间**：❓待研究 —— 无掩码方案在**生成类任务**上是否真的等价，素材只给了 GREEN +45% 一个指标。
→ 联动见 [[09-联动与索引]]

## B. 质疑对齐目标（「该拿什么当监督信号」）

### B1. 用 0/1 配对标签会造出假阴性
- **描述**：两个不同病人的报告都写"肺不张"，明明同类，却被当负样本强行推远。
- **谁提出的**：MedCLIP（EMNLP 2022，⚠️未建卡）→ [[MedFILIP]] 继续（指出其未解决透）。
- **证据**：
  - MedCLIP：语义匹配损失，MetaMap 抽 UMLS 实体做软标签。
  - MedFILIP：SSM 语义相似矩阵替代 0/1；消融 +SSM 73.3 → **74.7**。
- **是否解决**：🟡 部分。软标签有效，但**软标签本身依赖文本相似度计算的质量**（MedFILIP 依赖 GPT-3.5 抽取 + 相似度矩阵）。
- **剩余空间**：**软标签的监督信号本身是否干净？** 2026-11-10 组会列为"下一批可问的问题"之一（"监督信号干不干净"）。
→ 联动见 [[09-联动与索引]]

### B2. 只用疾病类名做监督，丢了上下文与子类
- **描述**：MedKLIP 一派抽病名做对齐，丢了"位置/程度/修饰"，也难处理子类。
- **谁提出的**：[[MedFILIP]]（Introduction 打靶"病名派 2a/2b"）。
- **证据**：memory/2026-10-27 四段式讲解。
- **是否解决**：🟡。MedFILIP 用 GPT-IE 补位置与程度；但**尺寸/数量信息丢失、形态被推给静态字典、多灶性（multiple lesions）无法表达**（memory/2026-10-27「可挑战的三个点」）。
- **剩余空间**：❌ **多灶性表达**是一个明确未解的口子。
→ 联动见 [[09-联动与索引]]

### B3. 固定融合权重不符合临床
- **描述**：图文的相对重要性**随病例变化**：糖网病灶典型，看图就够；中浆病灶特征重叠，报告价值更大。不能写死。
- **谁提出的**：[[M3GCD]]。
- **证据**：M3GCD 小组会讲稿背景痛点之二；memory/2026-11-10。
- **是否解决**：🟡。DEF 动态专家融合按样本分配权重；**但路由器学到的"重要性"是否真反映临床规律，还是记住了训练集噪声，论文未做归因**（组会批判第三条）。
- **剩余空间**：❌ **模态权重的可解释性没被验证**，这是明确缺口。
→ 联动见 [[09-联动与索引]]

## C. 质疑对齐粒度（「对齐到多细才够」）

### C1. 整图对整报告，属性被"平均掉"
- **描述**：一份报告包含疾病、位置、形态、程度四类信息，被压成一个向量，与整图对齐一次。
  MedFILIP 作者的用词是 **averaged（平均掉）而非 lost（丢掉）** —— 更麻烦，因为察觉不到、还会污染其他信息。
- **谁提出的**：[[MedFILIP]]。
- **证据**：MedFILIP 精读文字稿第二节；消融 +Entity 63.9→67.2、+FG →70.6。
- **是否解决**：🟡。拆属性有效，但拆分维度只有三元组（疾病/位置/程度）。
- **剩余空间**：**形态（morphology）词被推给了静态 Dictionary，缺动态建模**（memory/2026-10-27）。
→ 联动见 [[09-联动与索引]]

### C2. 按空间块切图，块里病灶和背景混着
- **描述**：GLoRIA 式局部对齐"切细了，但没切干净"。
- **谁提出的**：2026-11-10 组会口径（已获认可）。
- **证据**：memory/2026-11-10 时间线讲稿。
- **是否解决**：🟡。CP-CLIP 把主次分离从"切图"搬到"网络连接结构"。
- ⚠️ **2026-11-14 修正**：CP-CLIP 的真实目标是在**零样本**设定下提升能力，不是单纯解决粒度。判断本条是否值得做，要放在 zero-shot 语境下看。
- **剩余空间**：见 C3。
→ 联动见 [[09-联动与索引]]

### C3. 核心与外围的关系没有建模
- **描述**：CP-CLIP 把节点分为核心/外围，核心连所有、外围只连核心、外围之间不连。
  但**核心与外围之间是什么关系（谁影响谁、能否互相转换）没有建**。
- **谁提出的**：2026-11-10 组会（对 CP-CLIP Discussion 的解读）+ memory 中 M3GCD 关系判断。
- **证据**：memory/2026-11-10「三点注意：拆的是输入不是模型、外围不是丢掉是隔离、核心与外围的关系没建」；「CP-CLIP 的缺口 M3GCD 也没补上」。
- **是否解决**：❌ 未解决。
- ⚠️ **2026-11-14 修正（审阅 1.2）**：本条的**真实争议不是"对齐粒度"，而是"在零样本设定下对齐粒度值不值得"**。
  CP-CLIP 是**零样本医学图像分析**方法，有两条任务线：①zero-shot 分类（five public datasets）②关键区域检测/可解释性。
  改邻接矩阵这件事，在 CP-CLIP 自己的谱系里**已被用于提高可解释性 / 关键区域定位**。
  → 所以 I2 若只讲"关系没建"而不讲"我要在零样本赢还是可解释性赢"，**第一个问题就会被问撞车**。
- **剩余空间**：**仍大，但必须先定位赛道**（零样本 or 可解释性）。
→ 联动见 [[09-联动与索引]]

### C4. 对比学习只分离疾病大类，漏掉位置/大小/严重度
- **描述**：粗粒度疾病类分离导致表征次优。
- **谁提出的**：[[MedTrim]]（JBHI 2026）。
- **证据**：泛读摘要原话 "often focus on coarse-grained disease class separation and overlook fine-grained pathology attributes such as location, size, or severity"。
- **是否解决**：🟡。MedTrim 用实体感知三元组挖掘；MedFILIP 用 LLM + 视觉描述。
- **剩余空间**：两条路线（生成式 vs 本体判别式）**未做对照**（我的推导）。
→ 联动见 [[09-联动与索引]]

## D. 质疑模态权重（「图像和文本谁更重要」）

### D1. 粗粒度融合会把单模态独有信号平均掉
- **描述**：某些小病灶只在图像上看得见，粗暴加权平均会被文本整体"糊掉"。
- **谁提出的**：[[M3GCD]]（LEB 模块）。
- **证据**：M3GCD 小组会讲稿 P5；LEB 用"邻居内聚度"和"邻居熵"在无监督下衡量模态可靠度。
- **是否解决**：🟡。LEB 局部平衡有效；但**该可靠度指标在跨模态分布差异大时是否稳定，未验证**（我的推导，❓待确认）。
- **剩余空间**：可做。
→ 联动见 [[09-联动与索引]]

### D2. 文本单独用可能优于图像
- **描述**：M3GCD 观察到，在医学场景**纯文本单独用往往不比纯图像差、甚至更好**，因为报告语义密度高。
- **谁提出的**：[[M3GCD]]（论文观察）。
- **证据**：M3GCD 小组会讲稿第三节。
- **是否解决**：这不是"问题"而是"发现"，但**它反过来质疑了"必须做图文融合"的前提**。
- **剩余空间**：❌ **在什么条件下文本足够、什么条件下必须看图，没有量化边界**（我的推导）。
→ 联动见 [[09-联动与索引]]

## E. 质疑类别闭集（「只能分已知的类」）

### E1. 闭集分类无法覆盖新病种
- **描述**：传统分类"已知有哪些病，去分对"；疾病种类太多，无法穷举。
- **谁提出的**：[[M3GCD]]；[[MedFILIP]] 也从另一个角度提（IKI 让未见病可识别）。
- **证据**：M3GCD 讲稿背景三痛点；MedFILIP IKI 模块。
- **是否解决**：🟡。两条不同路线：
  - MedFILIP：靠"视觉描述"泛化到新病（但仍是已知类别集合内的零样本）；
  - M3GCD：靠聚类自动发现新类（真开放类）。
- **剩余空间**：**两条路线没有统一**——"能用视觉描述泛化的新病"与"聚类发现的新病"是同一件事吗？（我的推导，❓值得做）
→ 联动见 [[09-联动与索引]]

### E2. 要求预知未知类数量
- **描述**：现有 GCD 方法要求提前知道"未知类有几类"，现实做不到。
- **谁提出的**：[[M3GCD]]。
- **证据**：M3GCD 讲稿背景痛点之三；CD 模块用 Metropolis–Hastings 分裂-合并自动增减类别数。
- **是否解决**：🟡。M3GCD 声称解决；但**拆分合并的收敛性与稳定性未见充分验证**（组会批判：200 epoch、8 卡、标准差交代不足）。
- **剩余空间**：可做鲁棒性研究。
→ 联动见 [[09-联动与索引]]

## F. 质疑数据标注（「训练数据本身干不干净」）

### F1. 报告是非结构化的自然语言
- **描述**：机器读到的是一整句话，不知道哪个词是位置、哪个词是疾病、哪个词是程度。
- **谁提出的**：[[MedFILIP]]。
- **证据**：MedFILIP 精读文字稿问题 2。
- **是否解决**：🟡。GPT-IE 用 LLM 抽；但**抽取的准确性依赖 LLM，且三元组丢失了形态/尺寸/多灶性**（见 B2）。
- **剩余空间**：抽取器的误差如何传播到对齐损失，未见分析。
→ 联动见 [[09-联动与索引]]

### F2. 报告里存在否定与不确定性表述
- **描述**：报告常写"未见气胸""考虑感染"，否定和不确定需要专门处理，否则会把"没有"当成"有"。
- **谁提出的**：MultiCaRe-Thorax（J Imaging 2026，泛读候选第 4 条）——"annotations that inadequately account for linguistic negation and uncertainty"。
- **证据**：`泛读候选-医学图像文本分类.md` 第 4 条摘要。
- **是否解决**：🟡。该文提出 negation-aware NLP 框架；MedKLIP 一派用 present/uncertain/absent 三分类。
- **剩余空间**：**否定/不确定在对比学习软标签里怎么表达，未系统处理**（我的推导）。
→ 联动见 [[09-联动与索引]]
  → 注：MedFILIP 精读稿中"未见气胸"未被拆解，说明其模块对否定处理不明显（⚠️待核实原文是否另有处理）。

### F3. 图文配对不一定真配对
- **描述**：一份报告可能对应多次检查、多个体位；配对关系存在噪声。
- **谁提出的**：MedCLIP（解耦配对，(n+m)×(n+h)）。
- **证据**：memory/2026-10-26 MedCLIP 条目。
- **是否解决**：🟡。
- **剩余空间**：配对噪声的定量刻画（何时算噪声、噪声比例多少）素材中未见。
→ 联动见 [[09-联动与索引]]

### F4. 私有数据与真实报告依赖
- **描述**：M3GCD 强的前提是有"图像—真实临床报告"配对；拿不到配对文本，框架根基就塌了。
- **谁提出的**：组会对 M3GCD 的批判（我的批判性思考第二条）。
- **证据**：M3GCD 小组会讲稿第四节。用户自己的脑部CT项目改用手写提示词文本，**没有真实报告也能跑**。
- **是否解决**：❌ 未解决。这是**自己的差异化优势点**。
- **剩余空间**：**用"构造性文本"替代真实报告时，性能损失多少、能否补偿**，是一个可量化的研究问题。
→ 联动见 [[09-联动与索引]]

## G. 质疑评估方式（「我们量出来的东西算数吗」）

### G1. 指标不统一
- **描述**：有人报 ACC，有人报 AUROC，横向比较失真。
- **证据**：[[MedFILIP]] 用 ACC，CheXmix 用 AUROC（memory/2026-10-26）。
- **是否解决**：❌。
- **剩余空间**：可做「统一评测 + 可复现基准」类工作（工程量大）。
→ 联动见 [[09-联动与索引]]

### G2. 全科 VLM 在细胞形态学上接近随机
- **描述**：2026 的系统评测显示，GPT-4o / Gemini-2.0 / Llama-3.2 / DeepSeek-VL2 与 LLaVA-Med / CONCH / BiomedCLIP 在血细胞分类、骨髓细胞分类、宫颈涂片恶性检测上**零样本/少样本接近随机**（GPT-4o 零样本 F1 仅 0.22±0.02，少样本 0.36±0.03）。
- **谁提出的**：Kukuljan et al., Scientific Reports 2026（标题即 "Illusion of competence"）。
- **证据**：`泛读候选-医学图像文本分类.md` 第 5 条。
- **是否解决**：❌。这说明**"模型看起来很自信但解释不对"**。
- **剩余空间**：大 —— **可信度/校准（calibration）与对齐质量之间的关联**，素材中未见专文。
→ 联动见 [[09-联动与索引]]

### G3. 训练成本与可复现性
- **描述**：CheXmix 4×A100 80G、121 万步（"不可复现，只能读"）；M3GCD 200 epoch、8×RTX 4090；标准差交代不足。
- **证据**：memory/2026-10-26；M3GCD 小组会讲稿。
- **是否解决**：❌（结构性）。
- **剩余空间**：**轻量方案**（单卡可复现）在医学场景有现实价值 → 对应 [[06-创新点池]] 的 I3。
→ 联动见 [[09-联动与索引]]
